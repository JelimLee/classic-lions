사용자 본인이 공연장에서 찍은 사진 93장을 분류하고, 티켓을 판독해, **촬영일이 같은
시야 사진에 그 날의 좌석을 붙인** 결과다. 저작권은 사용자 본인에게 있다.

- 원본(읽기 전용): `~/Downloads/롯데콘서트홀 lf` 75장 / `~/Downloads/클래식 라이온즈` 18장

- 데이터: `app/data/seatViews.ts` (21건), `app/data/myEncores.ts` (2건)
- 판독 도구: `tools/photo_ocr.mjs` · 자산 생성: `tools/make_seatviews.py`

컨택트시트를 직접 눈으로 보고 한 장씩 분류했다.

**`view` 로 쓰지 않은 것 — 이유**

- **인물 사진 53장**: 사용자가 "시야 사진만" 이라고 명시했다. 롯데 75장 중 52장이
  객석을 배경으로 한 셀피/인물컷이다. 촬영일 정보만 참고에 썼고 자산으로 내보내지 않았다.
- **사람이 화면 앞을 가린 것**: 롯데 5번(앞사람 어깨가 좌측 1/3), 롯데 63번(얼굴 + 오르간),
  예당 5번(무릎·앞사람). 시야로서 값이 없어 뺐다.
- **시야가 아닌 것**: 롯데 60번(발·바닥), 롯데 65번(보면대 클로즈업 — 무대 위 소품이지
  객석 시야가 아니다).
- **티켓이 주인공인 컷**: 예당 9·10·13~17번은 뒤로 홀이 보이지만 티켓이 화면을 지배한다.
  `ticket` 으로 분류하고 시야 자산에서 뺐다.

**세로 사진 크롭 주의.** 시야 사진 21장 중 다수가 세로 프레임이라, 가운데를 그냥 자르면
프레임 아래쪽의 **프로그램북·앞사람 뒤통수**가 화면 절반을 먹는다. 그래서 사진마다
세로 앵커를 따로 지정했다 (`tools/make_seatviews.py` 의 `SPEC`). 어두운 예당 컷 3장은
세로 밝기 프로파일로 조명이 켜진 무대 밴드를 찾아 앵커를 맞췄다.

## 3. 앙코르 판독

**앙코르는 다른 어떤 소스에도 남지 않는다.** 로비 화이트보드에 손으로 적혔다 지워진다.
이 사진이 유일한 기록이고, 동시에 **검증할 방법이 전혀 없다.**

Gemini 전용 프롬프트(`tools/photo_ocr.mjs` 의 `ENCORE_PROMPT`)를 준비했으나
**일일 쿼터 소진으로 호출하지 못했다.** 대신 원본 3024×4032 에서 직접 읽었다
(`readMethod: 'agent-visual-read'`). 두 보드 모두 정자체에 가깝고 초점이 맞아
글자 자체는 또렷하다. 근거 크롭: `work/meta/encore/board_0325.png`, `board_0326.png`.

## 5. 못 한 것 · API 쿼터

**Gemini 무료 티어 일일 한도 소진.** 8건을 계획했으나 **3건만** 판독했다.

```
quotaId: GenerateRequestsPerDayPerProjectPerModel-FreeTier
metric : generativelanguage.googleapis.com/generate_content_free_tier_requests
limit  : 20, model: gemini-3-flash
```

- **성공한 호출: 3회** (롯데 티켓 3장). 429 거절 응답은 38회 더 받았다.
- 에러 메시지의 `Please retry in 55s` 는 **분당 한도처럼 보이지만 아니다.**
  `QuotaFailure.violations[].quotaId` 를 열어 보고서야 **일(day) 단위 한도**임을 확인했다.
  이 프로젝트의 다른 에이전트들과 키를 공유해서 20회/일이 이미 소진된 상태였다.
- 지시대로 무한 재시도하지 않고 중단했다.

**미실행 5건** — 쿼터 회복 후 `node tools/photo_ocr.mjs` 를 다시 돌리면 된다.
캐시가 남아 있어 성공한 3건은 재호출하지 않는다.

| 대상 | 종류 | 현재 상태 |
|---|---|---|
| `IMG_7968` 예당 2025-07-04 | ticket | 육안 전사로 대체 (§2-2) — OCR 로 교차 검증 필요 |
| `IMG_9741` 예당 2026-04-01 | ticket | 육안 전사로 대체 (§2-2) — OCR 로 교차 검증 필요 |
| `IMG_9618` 예당 2026-03-25 | encore | 육안 전사로 대체 (§3) — OCR 로 교차 검증 필요 |
| `IMG_9633` 예당 2026-03-26 | encore | 육안 전사로 대체 (§3) — OCR 로 교차 검증 필요 |
| `IMG_9624` 예당 2026-03-26 | ticket | **미판독.** 그 날 시야 사진이 없어 우선순위를 가장 낮게 뒀다 |

> 재실행 결과가 위 전사와 다르면 **사진을 다시 보고** 판단할 것. 둘을 섞지 말 것.

### 그 밖에 불확실한 것

- **어느 좌석이 사용자 자리인지 모른다** (§2-4). 티켓이 전부 2장씩이다.
- **좌석은 "그 날 그 자리"이지 "이 사진을 찍은 자리"가 아니다.** 같은 날 사진이라도
  로비나 무대 근처에서 찍은 컷이 섞일 수 있다. 티켓 좌석은 그 날의 관람석을 뜻한다.
- **2025-11-13 롯데 공연명 미상.** `KBS교향악단` 보면대만 단서다.
- **2026-03-26 앙코르 보드의 3번 줄 이후가 프레임 밖**이라 곡이 더 있었는지 모른다.

## 6. 검증

- `cd app && npx tsc --noEmit` → 에러 0
- 자산 파일 21개 == `SEAT_VIEWS` 21건, 파일명 완전 일치
