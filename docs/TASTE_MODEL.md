# 취향 분석 모델 — "낭만주의 좋아하시네요"를 넘어서

작성일: 2026-08-26
근거: 사용자 요구 — *"작곡가명만 하지 말고 교향곡·협주곡·피아노 솔로 이런 구성을 보고, 피아노 솔로가 좋은 건지, 그 곡은 왜 좋았던 건지, 어떤 구성이었는지 자세히 분석해달라"*

---

## 0. 왜 시대(era)만으로는 부족한가

현재 `UserProfile`의 취향 축은 `preferredEras` + `preferredInstruments` + `favoriteComposers` 세 개다. 이걸로 만들 수 있는 문장은 이 정도다:

> "낭만주의와 피아노를 좋아하시네요."

문제는 이게 **거의 모든 한국 클래식 관객에게 참**이라는 것이다. 변별력이 없다. 낭만주의 피아노 안에서도:

- 라흐마니노프 협주곡을 들으러 가는 사람 — **오케스트라와 겨루는 피아노**
- 쇼팽 녹턴 리사이틀을 가는 사람 — **혼자 있는 피아노**

이 둘은 완전히 다른 관객인데 현재 모델은 구분하지 못한다. 같은 `{romantic, piano}` 로 떨어진다.

**핵심 통찰**: 클래식 공연의 취향은 *무엇을* 듣느냐(작곡가·시대)보다 *어떤 형태로* 듣느냐(**편성·규모·프로그램 구성**)에서 더 크게 갈린다.

## 1. 새 취향 축

### 1-1. 편성 (forces) — 1순위 축

| 값 | 한국어 | 예시 |
|---|---|---|
| `symphony` | 교향곡 | 교향곡 5번, Symphony No.9 |
| `concerto` | 협주곡 | 피아노 협주곡 2번, Violin Concerto |
| `solo` | 독주 | 전주곡, 소나타, 에튀드, 녹턴 |
| `chamber` | 실내악 | 현악 사중주, 피아노 삼중주 |
| `orchestral_short` | 관현악 소품 | 서곡, 교향시, 무곡 |
| `vocal` | 성악·합창 | 가곡, 미사, 레퀴엠 |
| `stage` | 무대 | 오페라, 발레 |

### 1-2. 독주 악기 (soloist instrument)
협주곡·독주일 때만 유효. `piano` / `violin` / `cello` / `voice` / …

### 1-3. 규모 (scale)
`large`(풀 오케스트라) / `medium`(실내 오케스트라) / `small`(실내악) / `solo`(1인)

### 1-4. 프로그램 구성 (program architecture)
공연 **전체**의 형태. 곡 단위가 아니라 공연 단위 속성이다.

| 값 | 형태 | 설명 |
|---|---|---|
| `classic_three` | 서곡 → 협주곡 → 교향곡 | 오케스트라 정기연주회의 정통 구성 |
| `concerto_night` | 협주곡 중심 | 협주곡이 프로그램의 중심 |
| `recital` | 독주 리사이틀 | 한 연주자의 독주 위주 |
| `all_composer` | 올-작곡가 | 올-쇼팽, 올-베토벤 |
| `thematic` | 테마형 | "3개의 비창", "죽음과 소녀" 등 |
| `chamber_night` | 실내악 | |

### 1-5. 기존 축 (유지)
시대, 작곡가, 연주자.

## 2. 이 축들을 어떻게 얻는가 — **검색이 아니라 곡명 파싱**

가장 중요한 실무적 사실: **편성·규모는 곡 제목 문자열만으로 대부분 판정된다.** 검색도 LLM도 거의 필요 없다.

```
"라흐마니노프 피아노 협주곡 2번 Op.18"
   ├ 작곡가: Rachmaninoff        (작곡가 사전)
   ├ 편성:   concerto            ← "협주곡" 키워드
   ├ 독주악기: piano             ← "피아노" 키워드
   └ 규모:   large               ← concerto 규칙

"쇼팽 24개의 전주곡 Op.28"
   ├ 편성:   solo                ← "전주곡"은 독주 장르
   ├ 악기:   piano               ← 쇼팽 + 전주곡 → 피아노 (작곡가 기본악기)
   └ 규모:   solo
```

### 한국어 편성 키워드 사전 (초안)

| 편성 | 한국어 키워드 | 영어 |
|---|---|---|
| symphony | 교향곡, 심포니 | symphony |
| concerto | 협주곡, 콘체르토 | concerto |
| solo | 소나타, 전주곡, 에튀드, 연습곡, 녹턴, 야상곡, 발라드, 즉흥곡, 마주르카, 왈츠, 랩소디, 광시곡, 모음곡 | sonata, prelude, etude, nocturne, ballade |
| chamber | 사중주, 삼중주, 오중주, 이중주, 콰르텟, 트리오 | quartet, trio, quintet |
| orchestral_short | 서곡, 교향시, 환상곡, 무곡, 모음곡(관현악) | overture, tone poem, suite |
| vocal | 가곡, 연가곡, 미사, 레퀴엠, 칸타타, 오라토리오, 아리아 | lied, mass, requiem, cantata |
| stage | 오페라, 발레 | opera, ballet |

**주의할 예외**
- "모음곡"은 관현악(관현악 모음곡)일 수도, 독주(바흐 첼로 모음곡)일 수도 있다 → 작곡가·문맥 필요
- "환상곡"은 독주(쇼팽 환상곡)일 수도, 관현악(교향적 환상곡)일 수도
- 협주곡인데 독주 악기가 제목에 없는 경우 → 작곡가의 대표 협주곡으로 보정
- 편곡 버전 (피아노 편곡된 교향곡 등) → 원곡 편성이 아닌 실제 연주 편성 우선

→ **모호하면 `null` + 낮은 confidence.** 지어내지 않는다. 5장 §5 참조.

## 3. 분석 산출물 — 실제로 사용자에게 보이는 문장

### 나쁜 예 (현재 수준)
> "낭만주의와 피아노를 좋아하시네요."

### 좋은 예 (목표)
> **당신은 "낭만주의 팬"이 아니라 "비르투오소 피아노 팬"입니다.**
>
> 관람 12회 중 **9회에서 피아노가 독주 자리**에 있었습니다. 그중 6회가 협주곡 — 오케스트라와 겨루는 형태였습니다.
> 교향곡만으로 채워진 프로그램은 2회였고, 그 2회 모두 낮은 평가를 주셨습니다.
>
> 시대는 낭만주의(62%)에 몰려 있지만, 더 정확히는 **라흐마니노프·차이콥스키·리스트** 계열 — 기교가 전면에 드러나는 곡입니다.
> 같은 낭만주의여도 브람스 실내악은 한 번도 고르지 않으셨습니다.
>
> → 다음 추천: 조성진 × 라흐마니노프 협주곡 3번 (예술의전당, 10/14)

### 이 문장이 나오려면 필요한 데이터
1. 곡별 편성 태그 — §2 파싱
2. 공연별 프로그램 구성 — 곡 목록에서 도출
3. 피드백 — 어떤 공연에 좋다/싫다 했는지
4. **교차 집계** — "교향곡만 있는 공연 = 낮은 평가" 같은 상관

**3번(피드백)이 없으면 "왜 좋았는지"는 절대 못 만든다.** 관람 이력만으로는 "무엇을 봤는가"까지고, "무엇을 좋아했는가"가 아니다. 피드백 루프가 이 분석의 전제다.

## 4. 곡목 확보 — Cascade 전략

**전제: 티켓에는 곡목이 없다.** 한국 클래식 티켓엔 공연명(마케팅 제목)만 찍힌다. `"쇼스타코비치 3개의 비창"`은 공연 제목이지 곡명이 아니다.

따라서 곡목은 **다른 경로로 복원**해야 하고, 단일 경로로는 안 된다.

| 순서 | 방법 | 커버리지 | 신뢰도 | 자동화 |
|---|---|---|---|---|
| 1 | KOPIS / 공연장 페이지 매칭 | 중 | 높음 | 자동 |
| 2 | 리뷰 기사·블로그 검색 (날짜 대조 필수) | **낮음** | 중 | 자동 |
| 3 | **프로그램 북 촬영** | **높음** | **최고** | 반자동 (사용자 1회 촬영) |
| 4 | 사용자 직접 입력 | 100% | 높음 | 수동 |

### 각 경로의 한계 (솔직하게)
- **1번**: 지난 공연 페이지가 내려가는 경우가 많다. 사용자는 공연이 **끝난 뒤** 등록하므로 이게 치명적. → 조사 중
- **2번**: 리뷰 기사가 나는 공연은 극소수다. 조성진·임윤찬급이나 대형 내한만. 동네 리사이틀은 안 난다. 또 같은 공연명의 **다른 날짜** 공연과 혼동될 위험이 있어 날짜 대조가 필수.
- **3번**: 가장 정확하고 커버리지도 높다. 공연장에서 프로그램 북을 받으므로 티켓 찍는 김에 한 장 더 찍으면 된다. **이걸 주력으로 설계한다.**
- **4번**: 최후 수단이자 앵콜의 유일한 경로.

### 권장 UX 흐름
```
티켓 촬영 → OCR (공연명·날짜·장소·좌석)
   ↓
자동 시도: 1번 → 2번  (백그라운드, 사용자 대기 없음)
   ↓
   ├ 성공 → "이 곡들이 맞나요?" 확인 카드  (출처 표시)
   └ 실패 → "프로그램 북을 찍어주시면 곡목을 읽어드릴게요"  → 3번
   ↓
언제나: "앵콜은 무엇이었나요?" (선택 입력)
```

**모든 곡목에 출처(`source`)와 신뢰도를 기록한다.** `kopis` / `article` / `program_photo` / `user_input`. 나중에 분석의 신뢰도를 계산할 때 필요하고, 틀린 곡목이 취향 분석을 오염시키는 걸 추적할 수 있다.

### 앵콜

**⚠️ 2026-08-26 정정.** 이전 판에서 "앵콜은 당일 즉흥이라 인쇄물에도, KOPIS에도, 어떤 공개 데이터 소스에도 없다"고 단언했다. **틀렸다.**

틀린 이유는 **질문을 잘못 잡았기 때문**이다. "공연장이 앵콜을 기록하는가"를 물었고 그 답은 여전히 아니오다 — 예술의전당·롯데콘서트홀 모두 앵콜 게시판이 없다. 그러나 **악단은 기록한다.**

#### 확인된 앵콜 소스 (실측)

| 소스 | 규모 | 품질 | 확인 |
|---|---|---|---|
| **KBS교향악단 「앙코르곡」 게시판** | **93건, 2019-08~현재 연속** | 회차별 분리 · 한/영 병기 · 편곡자 표기 · 연주자 귀속 | 직접 fetch |
| 수성아트피아 「오늘의 앙코르」 | 68건 | **본문이 이미지** → OCR 필요. 대관 리사이틀까지 포함 | 하위 조사 |
| 부천필하모닉 「앵콜곡 안내」 | 상시 | 작품번호까지 포함 | 하위 조사 |

`kbssymphony.org/ko/info/notice.php?jb=1` — `jb=1` 이 앙코르곡 카테고리다. `공지사항`·`보도자료`와 나란히 **상설 카테고리로 분리** 운영된다.

본문 실물:
```
■ 공연명: KBS교향악단 제827회 정기연주회
■ 일시 및 장소: 2026.6.17-18.(수-목) 20:00, 롯데콘서트홀
■ 출연: 지휘 | 안드레스 오로스코-에스트라다 / 피아노 | 브루스 리우
○ 피아니스트 브루스 리우 앙코르
(17일) 드뷔시/꿈            Debussy / Rêverie
(18일) 차이코프스키 / 네 마리 백조의 춤   Tchaikovsky / Dance of the Four swans (arr. Earl Wild)
```

**이 프로젝트에 특히 중요한 이유**: 목록의 공연들이 **롯데콘서트홀·예술의전당에서 열린다.** 대상 두 홀과 정확히 겹친다. 공연장이 기록하지 않아도 악단 경로로 복원된다.

주목할 점 — **회차별로 앵콜이 다르다.** 위 예시에서 17일과 18일의 앵콜이 서로 다르다. 곡목 매칭에서 날짜 특정이 필요하다고 했는데, 앵콜에서는 그게 **훨씬 더 결정적**이다. 공연명만으로 매칭하면 틀린 앵콜을 붙인다.

⚠️ 파싱 주의: CMS 인코딩 문제로 `Rêverie` → `R?verie` 처럼 **비ASCII 문자가 `?` 로 치환**된다. 영문 곡명 정규화 시 처리 필요.

#### 복원율 (실측 기반)

| 공연 유형 | 복원율 | 경로 |
|---|---|---|
| KBS교향악단 정기·특별 | **~100%** | 공식 게시판 |
| 부천필 / 수성아트피아 | ~90% | 공식 공지 |
| 최상급 독주회·내한 (조성진·임윤찬 등) | 85~95% | 블로그 (단 앵콜 3~5곡이면 목록 불완전) |
| 서울시향 정기 | 50~70% | 아마추어 블로그 의존 |
| **일반 대관 독주회 (대다수)** | **5~15%** | 후기 존재율 자체가 낮음 |

**구조적 경고**: 기관이 한 번 게시했다고 지금 복원 가능한 게 아니다. 롯데 2017년 공지는 404, 경기아트센터 2023년 공지는 홈으로 리다이렉트된다. **게시 ≠ 현재 복원 가능.**

#### 설계 결론

앵콜은 **"복원되면 좋은 선택 필드"** 로 다룬다. 기본 경로는 여전히 사용자 입력이다. 다만:
- **KBS교향악단 게시판은 별도 커넥터를 붙일 가치가 충분하다.** 93건이 대상 두 홀에 걸쳐 있고 품질이 최상급이다.
- 자동 복원 시에도 **날짜까지 대조**해야 한다 (회차별로 다름).
- DB에 이미 있으면 확인만 받는다:
  ```
  "이 공연 앵콜이 드뷔시 〈꿈〉 맞나요?"  [맞아요] [아니요, 수정할게요]
  ```

앵콜은 취향 분석에서 **가중치가 높다** — 연주자가 그날 관객 반응을 보고 고른 곡이고, 관객 기억에 가장 강하게 남는 곡이기 때문이다.

## 5. 데이터 모델 확장

`ARCHITECTURE.md` §3의 `works` / `concert_program` 테이블에 편성 축을 추가한다.

```sql
ALTER TABLE works ADD COLUMN forces        TEXT;  -- symphony|concerto|solo|chamber|orchestral_short|vocal|stage
ALTER TABLE works ADD COLUMN soloist_inst  TEXT;  -- piano|violin|cello|voice|null
ALTER TABLE works ADD COLUMN scale         TEXT;  -- large|medium|small|solo
ALTER TABLE works ADD COLUMN forces_conf   REAL;  -- 파싱 신뢰도 0~1

ALTER TABLE concert_program ADD COLUMN source     TEXT;  -- kopis|article|program_photo|user_input
ALTER TABLE concert_program ADD COLUMN is_encore  INTEGER DEFAULT 0;
ALTER TABLE concert_program ADD COLUMN seq_conf   REAL;

ALTER TABLE concerts ADD COLUMN program_arch TEXT;  -- classic_three|concerto_night|recital|all_composer|thematic|chamber_night
```

`taste_profile.boosts` 도 확장:
```json
{
  "forces":       { "concerto": 0.42, "solo": 0.33, "symphony": 0.17, "chamber": 0.08 },
  "soloist_inst": { "piano": 0.71, "violin": 0.19 },
  "scale":        { "large": 0.58, "solo": 0.33 },
  "era":          { "romantic": 0.62, "classical": 0.21 },
  "program_arch": { "recital": 0.41, "classic_three": 0.33 }
}
```
이 분포가 곧 §3의 분석 문장을 만드는 재료이자, 추천 단계의 검색 부스팅 가중치가 된다.

---

## 6. 구현 순서

| 단계 | 내용 | 선행 조건 |
|---|---|---|
| 1 | 편성 키워드 사전 + 파서 (`parseForces`) | 없음 — **지금 바로 가능** |
| 2 | 작곡가 사전 (한↔영 매핑 포함) | 데이터 소스 조사 결과 |
| 3 | 프로그램 북 촬영 화면 + 곡목 OCR | 티켓 OCR 안정화 |
| 4 | 곡목 cascade (KOPIS → 기사 → 촬영 → 입력) | 2, 3 |
| 5 | 편성 기반 집계 + 분석 문장 생성 | 4 + 피드백 데이터 |
| 6 | 편성 부스팅을 추천 검색에 반영 | 5 + KOPIS 후보 풀 |

**1단계는 외부 의존이 없다.** 곡 제목 문자열만 있으면 되므로 지금 당장 만들 수 있고, 만들어두면 이후 모든 단계가 그 위에 쌓인다.

---

## 7. 정직하게 남겨둘 것

- **편성 파싱은 100%가 안 된다.** "모음곡", "환상곡" 같은 다의어와 편곡 버전이 있다. 목표는 완벽이 아니라 **높은 정확도 + 모호한 건 null**. 틀린 태그가 분석을 오염시키는 것보다 빈 태그가 낫다.
- **분석 문장은 표본이 작으면 위험하다.** 관람 3회로 "당신은 비르투오소 피아노 팬입니다"라고 단정하면 안 된다. 최소 표본(예: 8회)과 신뢰구간 개념을 UI에 반영하거나, 표본이 적을 땐 단정 대신 관찰("지금까지는 피아노 곡이 많았습니다")로 톤을 낮춘다.
- **피드백 없이는 "왜 좋았는지"를 만들 수 없다.** 관람 이력은 "무엇을 봤는가"일 뿐이다. 이 문서의 §3 예시 문장이 나오려면 ThumbsUp/Down이 실제로 작동해야 한다 (현재 더미 데이터 문제는 수정됨).
