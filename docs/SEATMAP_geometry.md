# SEATMAP_geometry — 픽셀아트 단면도 좌표 설계

> ## ⚠️ 이 문서는 【보관】 단면도(cross-section) 설계다
>
> 현재 기본 좌석표는 **위에서 본 평면도(top-down) 9격자**다.
> 각 층을 앞/중/뒤 × 좌/중/우 9칸으로 나누고, 무대 뒤 합창석은 격자 밖 별도 존이다.
>
> - 구현: `app/services/seatGeometry.ts` (존 표 + 층 평면), `app/components/seatmap/`
> - 렌더 확인: `docs/seatmaps/render_topdown_lotte.png`, `render_topdown_sac.png`
> - 왜 바꿨나: 예당 공식 XLS 가 **셀 하나 = 좌석 하나인 평면 격자**라 top-down 이
>   원자료에 그대로 대응한다. 그리고 단면도의 최대 약점이던 `tier`(층 높이 —
>   51개 블록 전부 추정값)가 평면도에서는 **아예 필요 없다.**
>
> 아래 §1~§8 은 단면도 뷰의 설계이고, 그 코드는 지우지 않고 옮겨 보관했다:
> `app/services/crossSectionGeometry.ts`, `app/components/seatmap/halls/cross-section/`.
> 나중에 "세 번째 뷰"로 되살릴 때 이 문서를 그대로 쓰면 된다.
>
> **top-down 의 9격자 매핑 규칙은 `seatGeometry.ts` 상단 주석과 `ZONE_SPECS` 표가
> 단일 출처다** — 여기에 중복해서 적지 않는다 (둘이 어긋나는 게 제일 나쁘다).

---

> 대상: `app/data/venues.ts` 의 `VenueProfile` → 아트 캔버스 좌표 변환.
> 목표: 사용자가 "내가 **그 홀**에 앉아 있다"고 느끼게 하는 것. 대충 그린
> 공연장 일러스트가 아니라, 롯데콘서트홀과 예술의전당 콘서트홀이 **서로 다르게**
> 보여야 한다. 두 홀은 실제로 근본적으로 다른 구조다.

## 0. 한 장 요약

| | 롯데콘서트홀 | 예당 콘서트홀 |
|---|---|---|
| 형식 | **빈야드**(포도밭) | **아레나형 부채꼴** (공식 표현) |
| 무대 위치 | 홀 **한가운데** | 홀 **한쪽 끝** |
| 층수 | 2층 | 3층 |
| 단면 실루엣 | 낮고 넓다. 무대를 중심으로 **양쪽**이 올라간다 | 높고 비대칭. 한쪽 끝에 3단이 **쌓인다** |
| 무대 뒤 좌석 | P / LP / RP (합창석+터레이스) | G / H / F (합창석 274석) |
| 특징적 실루엣 | 무대 뒤 벽면의 **파이프오르간 파사드** | 말굽처럼 감아 도는 **2·3층 팔** + BOX 12개 |
| 좌석수 | 2,036 (1층 1,538 / 2층 498) | 2,505 (1,508 / 568 / 429) |

단면도 하나로 두 홀을 다 그리려 하면 둘 다 밋밋해진다. **캔버스와 스프라이트만
공유하고 실루엣은 완전히 따로 만든다.**

## 1. 캔버스

```
ART_W = 160
ART_H = 104     ← 선행 리서치의 96 에서 +8
```

**왜 96 이 아니라 104 인가.**
- 예당은 3층 + M/N 뒷줄까지 있다. 96 으로 잡으면 무대 바닥(y≈80)과 천장 사이
  60px 안에 3개 층 밴드를 넣어야 해서 층당 9px 미만이 된다.
  아바타 스프라이트가 **5w × 7h** 인데 9px 밴드에 넣으면 층 경계선과 머리가 붙는다.
- 롯데는 반대로 무대 뒤 **파이프오르간 파사드**가 실제로 홀에서 제일 눈에 띄는
  요소인데(공식 배치도에도 `PIPE ORGAN` 이 따로 표기돼 있다), 96 에서는 그릴
  세로 공간이 안 나온다. 이게 없으면 롯데 단면이 "그냥 객석"이 된다.
- 104 는 8의 배수라 정수 배율에서 깨지지 않는다.
  - 2x → 320 × 208 (모바일 390px 뷰포트에 들어간다)
  - 4x → 640 × 416 (데스크톱 카드에 들어간다)

**한 캔버스를 두 홀이 공유한다.** 홀마다 캔버스 크기를 바꾸면 아바타 스프라이트,
지터 상수, 최소 클릭 영역이 전부 홀마다 갈라진다. 밴드 배치만 다르게 한다.

### 확대는 정수 배율만

```css
.seatmap { image-rendering: pixelated; }
/* scale ∈ {1, 2, 4} */
```

1.5x·3x 를 허용하면 안 되는 이유는 성능이 아니라 **아바타가 망가지기 때문**이다.
1.5x 에서 5px 폭 스프라이트는 7.5px 로 리샘플되고, 눈 1px 은 어떤 픽셀은 1px,
어떤 픽셀은 2px 이 된다. 얼굴이 비대칭이 되고 층 경계선 굵기가 들쭉날쭉해진다.

컨테이너 폭 `W` 에서 배율 고르기:

```ts
const scale = W >= 640 ? 4 : W >= 320 ? 2 : 1;
```

1x(160px)는 아바타가 5px 라 사실상 안 보인다. **출하 최소 배율은 2x** 로 본다.
1x 는 썸네일/미리보기 전용.

## 2. 단면 실루엣

기호: `▛▀▜` 구조물 · `▄▃▂` 좌석단 · `░` 단면 절단면 밖(접어서 표시) · `═` 바닥

### 2-1. 롯데콘서트홀 — 무대가 가운데인 빈야드

무대가 홀 중앙에 있고 객석이 360° 둘러싼다. 그래서 **종단면이 자연스럽게
양쪽으로 갈라진다** — 이건 단점이 아니라 이 홀의 정체성이다.

```
      ← 무대 뒤(합창석)        무대        객석 →
   ┌────────────────────────────────────────────────────────────┐ y=4
   │   ┌──────────────┐                                          │
   │   │ ▒▒ PIPE ▒▒▒▒ │  ← 오르간 파사드 (x 8..40, y 8..30)      │
   │   │ ▒▒ ORGAN ▒▒▒ │     롯데에만 있다                        │
   │   └──────────────┘                                          │
   │                                                             │
   │                                             ▄▄▄▄▄▄▄  ← 2F   │ y=32
   │                                         ▄▄▄▄  A~E 1~8열     │
   │        ░░░░░░░ 2F L/R (2열, 벽 따라 길게) ░░░░░░░░░          │ y=46
   │                                                             │
   │      ▟▛ P6                                        ▗▄▞ 23열  │
   │    ▟▛  P4          ┏━━━━━━━━━━━┓           ▗▄▄▞▘            │
   │  ▟▛  P1            ┃   STAGE   ┃      ▗▄▄▞▘  1F A~E         │ y=76
   │ ▛ LP/RP  ░L/R░     ┃           ┃  ▗▄▞▘ 1열   ░L/R░          │
   ══════════════════════┻━━━━━━━━━━━┻══════════════════════════  y=84
   └────────────────────────────────────────────────────────────┘ y=100
    x=8     x=34   x=52 x=56    x=86 x=90            x=150
```

읽는 법: 무대(x 56..86)를 기준으로 **왼쪽이 무대 뒤**, 오른쪽이 객석이다.
1층 A~E 는 1열(무대 앞)에서 23열까지 오른쪽 위로 완만히 올라가고,
P 는 무대 뒤에서 왼쪽 위로 더 가파르게 올라간다.
2층은 하나의 층이 아니라 **긴 측면 발코니(L/R)** 와 **뒤쪽 발코니(A~E)** 두
덩어리로 갈라져 있고, 측면 발코니가 무대 옆까지 뻗어 나가는 게 이 홀의 특징이다.

### 2-2. 예술의전당 콘서트홀 — 한쪽 끝에 3단이 쌓인 부채꼴

무대가 끝에 있고 객석이 한 방향으로만 펼쳐진다. 대신 **뒤쪽에서 3층이 수직으로
쌓이면서** 위로 높아진다. 롯데와 반대 방향의 실루엣이다.

```
    무대뒤  무대                    객석 →
   ┌────────────────────────────────────────────────────────────┐ y=6
   │                                                             │
   │                                          ▄▄▄▄▄▄  ▛M/N▜      │ y=18
   │                                     ▄▄▄▄▄  3F A~G 1~7열     │
   │                 ░BOX7~12░                                   │ y=30
   │                                                             │
   │                                       ▄▄▄▄▄▄▄               │ y=44
   │                                  ▄▄▄▄▄  2F A~E 1~8열        │
   │              ░BOX1~6░                                       │ y=50
   │                                                             │
   │    ▟▛ G4                                     ▗▄▄▞▘ 22열     │
   │  ▟▛  G1     ┏━━━━━━━━━┓            ▗▄▄▄▞▘                   │ y=70
   │ ▛ ░H/F░     ┃  STAGE  ┃     ▗▄▄▄▞▘   1F A~E 1~22열          │
   ══════════════┻━━━━━━━━━┻══════════════════════════════════   y=88
   └────────────────────────────────────────────────────────────┘ y=100
    x=10  x=22  x=26   x=56 x=60                x=126     x=152
```

두 그림의 차이가 곧 두 홀의 차이다:
- 롯데는 **가로로 퍼지고**(무대 양쪽), 예당은 **세로로 쌓인다**(뒤쪽 3단).
- 롯데는 오르간 파사드가 화면 왼쪽 위를 채우고, 예당은 그 자리가 비어 있다.
- 예당에만 BOX 12개가 무대 양옆에 떠 있다.
- 롯데 1층은 앞뒤 폭 23열로 짧고 완만, 예당 1층은 22열이지만 부채꼴이 더 길게 눕는다.

## 3. 빈야드/감싸는 객석을 단면에 어떻게 담나

### 문제
두 홀 다 객석이 무대를 둘러싼다. 순수한 옆 단면(하나의 절단면)으로는
- 무대 **뒤** 합창석(예당 G/H/F 274석, 롯데 P/LP/RP)이 무대와 겹치고,
- 무대 **옆** 좌석(롯데 L/R, 2층 L/R, 예당 BOX·2·3층 팔)은 절단면 밖이라
  아예 안 보이거나 객석과 x 가 겹친다.

### 해법 — 세 가지를 나눠 쓴다

**(a) 무대 뒤는 겹치지 않는다. 겹칠 이유가 없다.**
깊이 축을 **부호 있는 값**으로 잡고 무대를 x=0 이 아니라 **캔버스 안쪽**에 둔다.
무대 뒤 좌석은 무대의 **왼쪽**에, 객석은 오른쪽에 놓인다. 겹침 자체가 사라진다.
롯데는 원래 무대가 한가운데라 이게 물리적으로도 맞다.
예당도 합창석이 진짜로 무대 뒤에 있으니 맞다.

**(b) 절단면 밖(측면) 블록은 "접어서" 그린다 — 다른 렌더 스타일로.**
롯데 L/R·2층 L/R, 예당 H/F·BOX 는 단면 평면에 없다. 이걸 그냥 채워 그리면
"객석 한가운데 떠 있는 정체불명의 단"이 된다. 규칙:

| | 절단면 안 (A~E, C, G …) | 절단면 밖 (L/R, BOX, H/F …) |
|---|---|---|
| 좌석단 | 꽉 찬 픽셀 `▄` | 1px 외곽선 + 45° 해칭 `░` |
| 밝기 | 100% | 60% |
| 아바타 | 그대로 | 그대로 + 1px 후광 |

"반투명하게 접혀 있다"는 시각 문법이 생기면, 사용자는 자기가 벽 쪽 단에 앉았다는
걸 오히려 **더** 잘 안다. 롯데 L/R 은 실제로 벽 쪽 높은 단이고, 그 느낌이 맞다.

**(c) 좌우는 단면이 절대 표현 못 한다 → 인셋 미니 평면도로 뺀다.**
`side-left` / `side-right` 를 x 로 옮기면 깊이가 거짓말이 된다. 그래서 좌우는
좌표에서 빼고 **24×18 픽셀 인셋**(우상단)에 넣는다. 위에서 본 홀 윤곽 + 무대 +
내 위치 1px. 여기에 더해 아바타 스프라이트를 좌우 미러링한다
(왼쪽 블록이면 오른쪽을 보고 앉은 모습 = 무대를 향한다).

```
   ┌────────────┐
   │  ╭──────╮  │   인셋 (24×18)
   │  │▁▁██▁▁│  │   ██ = 무대
   │  │▁▁▁▁▁▁│  │   ●  = 나
   │  │▁●▁▁▁▁│  │
   │  ╰──────╯  │
   └────────────┘
```

## 4. `seatToXY()` 매핑 규칙

### 4-1. 자료구조

```ts
type Precision = 'exact' | 'row' | 'block' | 'floor' | 'none';

interface Placement {
  x: number;                    // 0..ART_W-1
  y: number;                    // 0..ART_H-1
  side: 'left' | 'right' | 'center';
  precision: Precision;
  /** block.conf.geometry — UI가 "≈" 를 붙일지 결정 */
  geometryConfidence: Confidence;
  /** true 면 절단면 밖 = 해칭 스타일로 그린다 */
  folded: boolean;
}

/** 블록 하나를 캔버스 위 선분으로 고정한다. */
interface BlockAnchor {
  code: string;
  floor: number;
  near: { x: number; y: number };   // 무대에 가장 가까운 끝
  far:  { x: number; y: number };   // 무대에서 가장 먼 끝
  side: 'left' | 'right' | 'center';
  folded: boolean;
  /** seatAxis==='depth' 인 블록에서 near..far 에 대응하는 좌석 번호 범위 */
  seatSpan?: [number, number];
}
```

블록은 **점이 아니라 선분**이다. 열(또는 좌석 번호)이 그 선분 위의 위치를 정한다.

### 4-2. 깊이 비율 t 를 구한다 (0 = 무대 쪽 끝, 1 = 먼 끝)

```ts
function depthFraction(b: VenueBlock, a: BlockAnchor, s: ParsedSeat)
  : { t: number; precision: Precision } {

  // (1) 열이 곧 깊이인 블록 — 대부분의 정면 객석
  if (b.rowAxis === 'depth' && s.row != null && b.rowMin != null && b.rowMax != null) {
    const span = Math.max(1, b.rowMax - b.rowMin);
    const t = clamp01((s.row - b.rowMin) / span);
    return { t, precision: s.seat != null ? 'exact' : 'row' };
  }

  // (2) 열이 "높이"고 깊이는 좌석 번호인 블록
  //     롯데 L/R·LP/RP·2층 L/R, 예당 H/F, 예당 2·3층 팔(A/E, A/G)
  if (b.seatAxis === 'depth' && s.seat != null && a.seatSpan) {
    const [s0, s1] = a.seatSpan;
    const u = clamp01((s.seat - s0) / Math.max(1, s1 - s0));
    // ⚠️ 좌우 대칭 짝이라도 방향이 반대일 수 있다. venues.ts 의 seatDepthDir 참고.
    const t = b.seatDepthDir === 'toward' ? 1 - u : u;
    return { t, precision: 'exact' };
  }

  // (3) 블록만 안다
  return { t: 0.5, precision: 'block' };
}
```

**(2)가 왜 필요한가.** 롯데 2층 L 은 열이 1·2 밖에 없다. 열로 깊이를 계산하면
34m 짜리 긴 발코니 전체가 2px 안에 뭉친다. 실제로 이 발코니에서 깊이를 결정하는
건 좌석 번호(1번이 무대 쪽, 34번 이상이 뒤쪽)다. 예당 2층 A/E, 3층 A/G 도 같다 —
게다가 **예당은 좌석 번호를 평면도 왼→오른쪽으로 매기기 때문에 왼쪽 팔(A)과
오른쪽 팔(E)의 깊이 방향이 서로 반대다.** `seatDepthDir` 가 이걸 담는다.

### 4-3. x, y

```ts
const t = depthFraction(...).t;
const x = Math.round(lerp(a.near.x, a.far.x, t));
const y = Math.round(lerp(a.near.y, a.far.y, t));
```

앵커 선분이 이미 경사(rake)를 담고 있으므로 y 를 따로 계산하지 않는다.
`near.y > far.y` 로 두면 뒤로 갈수록 자동으로 올라간다.

**`tier` 는 좌표 계산에 쓰지 않는다.** `venues.ts` 가 명시하듯 tier 는 51개 블록
전부 추론값이다(`conf.tier === 'inferred'`, 예외 없음 — 공식 배치도가 전부
평면도라 높이 정보가 아예 없다). 추론값을 y 에 직접 곱하면 틀린 높이가 그대로
화면에 나온다. tier 는 **같은 층 안에서 밴드를 겹치지 않게 정렬하는 순서**로만
쓰고, 그 순서가 만드는 y 차이는 밴드 안에서 최대 ±4px 로 묶는다.
tier 가 틀려도 사용자가 "층이 틀렸네"라고 느낄 일은 없게.

### 4-4. 좌우 지터 (선택)

좌석 번호를 알면 블록 안 가로 위치를 **±1px 안에서만** 흔든다.

```ts
const lateral = (s.seat - 1) / Math.max(1, maxSeatInRow - 1); // 0..1
x += Math.round((lateral - 0.5) * 2);   // -1, 0, +1
```

2px 이상 흔들면 깊이 정보와 섞여서 거짓말이 된다. 좌우는 인셋이 담당한다.

### 5-3. 앵커 값의 신뢰도 — 이건 실측이 아니다

앵커 픽셀 좌표는 **공식 자료에서 자동으로 나온 값이 아니다.** 근거의 층위가 다르다:

| 항목 | 근거 | 신뢰도 |
|---|---|---|
| 블록의 **순서**(누가 무대에 더 가까운가) | 예당은 공식 엑셀 격자의 행/열 인덱스, 롯데는 공식 배치도 판독 | 높다 |
| 블록의 **좌우** | 〃 | 높다 |
| 블록의 **상대 길이** | 엑셀 격자 폭 / 배치도 비율 | 중간 |
| 픽셀 **절대 좌표** | 위 비례를 캔버스에 손으로 맞춘 값 | **낮다 — 디자인 값이다** |
| 층 **높이**(y 밴드) | 어느 자료에도 없다. `conf.tier === 'inferred'` | **낮다** |

특히 예당 엑셀은 각 블록을 **직사각형으로 펴서** 배치한다(2층이 A\|B\|C\|D\|E 가로
일렬). 실제 2·3층은 말굽처럼 휜 팔이다. 그래서 **개수·열 범위는 엑셀, 공간 배치는
공식 배치도 이미지**를 믿었고, 엑셀 격자 행 번호를 실제 거리로 환산하지 않았다
(격자 행 간격이 실제 거리에 비례하지 않는다 — 무대 구간은 압축돼 있다).
`venues.ts` 의 `conf.geometry` 가 팔·윙 블록에서 `inferred` 인 이유가 이것이다.

참고로 엑셀에서 무대 위치: 「콘서트홀1층」 시트 **13행 23열** 셀 = `무 대`,
「콘서트홀2,3층」 시트 **4행 37열** = `무 대`. 두 시트 모두 무대가 위, 객석이 아래다.

## 6. 좌석 정보가 불완전할 때

사용자 데이터의 상당수가 불완전하다. 실제 정답지에 `'1층'`, `'1층 E블록'` 같은
값이 흔하다. **모르는 걸 그럴듯하게 채우지 않는 게 이 화면의 핵심 요구사항이다.**

| 아는 것 | precision | 어디에 찍나 | 어떻게 보이나 |
|---|---|---|---|
| 층 + 블록 + 열 + 번 | `exact` | 앵커 보간 + 좌우 지터 | 아바타 1개, 또렷하게 |
| 층 + 블록 + 열 | `row` | 앵커 보간, 지터 없음 | 아바타 1개 |
| 층 + 블록 | `block` | t=0.5 (블록 한가운데) | 아바타 + **블록 선분 전체를 은은하게 강조** |
| 층만 | `floor` | 아래 층 대표점 | 아바타 반투명 + **층 밴드 전체 강조** + "1층 어딘가" 라벨 |
| 공연장만 | `none` | **아바타를 안 그린다** | 홀 실루엣만. "좌석 정보 없음" |
| 지원 안 하는 홀 | – | **아무것도 안 그린다** | "이 공연장은 아직 좌석도가 없어요" |

층 대표점 (그 층에서 가장 큰 블록의 한가운데. 진짜 좌석수 가중 무게중심을 쓰면
합창석이 무게중심을 무대 안으로 끌고 들어가서 이상해진다):

| | 1층 | 2층 | 3층 |
|---|---|---|---|
| 롯데 | (120, 74) C구역 12열쯤 | (140, 38) 2F C 4열쯤 | – |
| 예당 | (93, 78) C블록 11열쯤 | (116, 49) 2F C 4열쯤 | (109, 29) 3F D 5열쯤 |

### 신뢰도를 화면에 반영하기

`venues.ts` 는 블록마다 `conf.{existence,rows,seatCount,geometry,tier}` 를 준다.
레거시 `conf` 종합값 `block.confidence` 는 `worstOf(existence, rows, geometry)` 다.

- `conf.geometry === 'inferred'` → 아바타 옆에 `≈` 또는 1px 흔들림.
  (예당 2·3층 팔, 예당 H/F, 롯데 LP/RP 8개 블록)
- `conf.rows === 'unknown'` → 열 보간을 **하지 마라**. t=0.5 고정, precision 을
  `block` 으로 내려라. (예당 BOX 12개가 전부 여기 해당 — 박스 안 열 번호
  체계를 확인하지 못했다.)
- `tier` 는 어떤 경우에도 툴팁에 "확인됨"으로 표시하지 마라. 51개 전부 추론이다.

## 7. 구현 순서 제안

1. 캔버스 + 두 홀의 정적 실루엣 (아바타 없이). 두 그림이 서로 달라 보이는지 먼저 확인.
2. `BlockAnchor` 표를 상수로 넣고 `seatToXY` 의 (1) 경로만 구현 — 정면 객석.
   이게 실제 티켓의 대다수를 덮는다.
3. `precision` 별 렌더 상태 5가지. **`none` 과 지원 안 하는 홀을 먼저** 만들어라.
   틀리게 그리는 것보다 안 그리는 게 낫다는 규칙을 코드 구조로 못박는다.
4. (2) 경로 — seat 축 블록. 롯데 2층 L/R 과 예당 팔.
5. 인셋 미니 평면도 + 스프라이트 미러링.
6. 해칭(folded) 스타일.

## 8. 검증 방법

- **눈으로**: 사용자가 실제로 다니는 홀이다. 롯데 1층 C 12열, 예당 2층 A 3열처럼
  본인이 앉아본 자리를 넣고 "여기 맞아?"를 직접 물어보는 게 제일 빠른 검증이다.
- **자동으로**: 모든 블록 × (rowMin, 중간, rowMax) 조합을 돌려서
  - 좌표가 캔버스 밖으로 안 나가는가
  - 같은 층에서 열이 커질수록 x 가 단조 증가(또는 감소)하는가
  - 무대 상자 안에 좌석이 찍히지 않는가
  - 층이 높을수록 y 가 작은가
- **회귀**: `matchVenue('예술의전당 CJ토월극장') === null` 이 깨지면 그 즉시
  사용자가 안 가본 홀에 앉는다. 이건 반드시 테스트로 고정해 둘 것.
